# Starport Market 玩法 v3 — 设计简报

## 现有玩法（v2）一页概括

18 夜经营。每夜：看事件 + 今晚客群 → 决策（8 货品各自进货量 0-99 与标价 / 可选广告 1 of 5 / 可选升级 1 of 7 / 执照二选一 / 悬赏自动结算）→ 开市结算：悬赏优先按高价收购 → 散客需求 = 基础需求 × 事件乘数 × 客群偏好(+18%/tag) × 价格弹性 pow(2−价格比, 敏感度×0.55) × 广告加成 × 声望(±0.4%/点) × 噪声±12% → 卖出 min(库存,需求) → 过期损耗（shelf_life 批次制，FIFO）→ 租金 $6 + 损耗费 $1/件 → 声望结算 → 里程碑检查。终局分 = 营收 + 2×现金 + 5×声望 − 3×损耗。

代码：`godot/scripts/core/market_game.gd`（817 行，确定性 RNG，try_quote/try_step/observation/terminal_summary 接口）；数值内容全在 `godot/data/content.json`（8 货品 / 6 客群 / 13 事件 / 7 升级 / 5 广告 / 10 执照 / 11 里程碑 / 悬赏配置）。

## 诊断：为什么拉跨

1. **决策全是可算的，没有权衡**：定价对着预测微调、进货照预测买、执照挑大数、升级有钱就买。玩家不需要"判断"，只需要"执行"。
2. **悬赏 = 白送**：单价远超成本，无条件必接必赚，唯一成本是占容量。没有失败惩罚、没有取舍。
3. **无赛季弧线**：18 夜机械重复，租金/容量/压力恒定；终夜只是需求乘数最大的事件，玩家无法"备战"。
4. **无失败压力**：起手 $120、租金 $6，破产条件（现金<0 且零库存）形同虚设。全程零风险 → 零张力。
5. **声望无感**：0.4%/点的需求影响；loyalty_bias 基本未使用；没有围绕声望的决策。
6. **事件/客群只是乘数**：不附带决策；明天的事件不可见 → 无法提前布局。
7. **无跨夜策略**：没有价格记忆/回头客、囤货投机只是隐性存在（非刻意设计）、无长线合同。
8. **分数黑箱**：玩家无法围绕终局目标做中途决策。
9. **广告性价比含糊 + 背刺纯随机**：+2~4 需求 vs $25-70 成本，多数情况不值；12%×风险的背刺没有决策含量。

## v3 设计目标

- 每夜至少 2-3 个"没有标准答案"的权衡决策；跨夜有可规划的长线策略。
- 有张力：风险要真实存在（可失败/可爆亏），回报要配得上风险；有推运气（push-your-luck）时刻。
- 有赛季弧线：压力递增、阶段目标、可预见并为之备战的终局。
- 事件与客群从"乘数"变成"带决策的机会"。
- 声望/关系成为真实资源。
- 单局 15-25 分钟，中文文案，赛博夜市烟火气。

## 硬约束

- 保持核心身份：星港夜市摆摊、夜循环（规划→开市→结算）、8 货品 + tag 体系、事件、客群、悬赏、执照概念可重构但要留其神。
- 架构不变：确定性 seed（同 seed 同结局）、规则全在 market_game.gd + content.json（数值驱动）、try_quote/try_step/observation/terminal_summary 四接口模式保留（字段可扩展）。
- UI 承载力：决策面 ≈ 现有备货屏 + 至多 1-2 个新面板/弹层；不能变成需要十个界面的重游戏。结算屏可以加"当夜小抉择"弹层（最多一个、二/三选一按钮式）。
- 单人、无实时操作、回合制结算。
- 实现语言 GDScript；smoke_test.gd / screenshot.gd 会同步改写，不构成约束。
- Python 原型 starport_market/core.py 允许分叉（Godot 版为正典），README 同步更新。
